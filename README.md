

Вебсервіс для скорочення довгих URL-адрес, розроблений на **Node.js** та **Express.js 5** із використанням **PostgreSQL** для постійного збереження даних.

Проєкт реалізовано за підходом **Design First**: спочатку створено контракт API у специфікації **OpenAPI 3.1** (`openapi.yaml`), після чого на його основі реалізовано сервіс та налаштовано інтерактивну документацію за допомогою Swagger UI.

## Використані технології

| Категорія | Технології |
|---|---|
| Runtime | Node.js |
| Backend | Express.js 5 |
| База даних | PostgreSQL |
| Робота з БД | pg-promise |
| Конфігурація | dotenv |
| API-специфікація | OpenAPI 3.1, YAML |
| Документація API | Swagger UI, swagger-ui-express |
| Валідація OpenAPI | @redocly/cli |
| Контейнеризація | Docker, Docker Compose |

## Структура проєкту

Основні файли проєкту:

- `openapi.yaml` — специфікація API у форматі OpenAPI 3.1.
- `Dockerfile` — інструкції для створення Docker-образу застосунку.
- `compose.yaml` — конфігурація сервісів Docker Compose.
- `initdb.sql` — SQL-скрипт початкової ініціалізації бази даних.
- `.env.sample` — приклад конфігурації змінних середовища.
- `.env` — локальні налаштування проєкту (не додається до Git).

## Вимоги для запуску

Перед початком роботи необхідно встановити:

- [Node.js](https://nodejs.org/) — за потреби для локальної розробки.
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) або Docker Engine із підтримкою Docker Compose.
- [Git](https://git-scm.com/).

**Примітка:** для запуску всього проєкту через Docker Compose достатньо встановленого та запущеного Docker.

## Запуск проєкту з нуля

### 1. Клонування репозиторію

Відкрийте термінал і виконайте команди:

```bash
git clone <URL_ВАШОГО_РЕПОЗИТОРІЮ>
cd lab6-url-shortener
```

### 2. Налаштування змінних середовища

Створіть файл `.env` на основі шаблону `.env.sample`:

```bash
cp .env.sample .env
```

Відкрийте файл `.env` та заповніть необхідні параметри:

```env
PORT=8080
BASE_URL=http://localhost:8080

DB_HOST=db
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=change_me_please
DB_NAME=shortener_db
```

**Важливо:** значення `DB_HOST=db` необхідно залишити саме таким під час запуску через Docker Compose, оскільки `db` — це назва сервісу бази даних у `compose.yaml`.

Файл `.env` містить локальні налаштування та пароль до бази даних, тому він доданий до `.gitignore`. У репозиторії зберігається лише шаблон `.env.sample`.

### 3. Запуск Docker-контейнерів

Для створення необхідних образів і запуску застосунку разом із базою даних виконайте:

```bash
docker compose up --build -d
```

Ця команда:
- створює Docker-образ застосунку;
- запускає контейнер із PostgreSQL;
- запускає вебсервіс;
- налаштовує взаємодію між контейнерами;
- забезпечує постійне збереження даних бази даних за допомогою іменованого тому `db-data`.

### 4. Перевірка роботи сервісу

Після запуску контейнерів перевірте стан сервера та підключення до бази даних:

```bash
curl -i http://localhost:8080/health
```

Якщо все працює правильно, сервер поверне статус **HTTP 200** та відповідь:

```json
{
  "status": "ok",
  "database": "connected"
}
```

Це означає, що вебсервер запущений і успішно підключився до PostgreSQL.

### 5. Перегляд документації API

Після успішного запуску сервісу документація доступна за такими адресами:

| Ресурс | URL |
|---|---|
| Swagger UI | http://localhost:8080/docs |
| OpenAPI у форматі JSON | http://localhost:8080/openapi.json |
| Перевірка стану сервісу | http://localhost:8080/health |

У **Swagger UI** можна переглядати доступні кінцеві точки API, ознайомлюватися з параметрами запитів, моделями даних та тестувати запити безпосередньо через браузер.

## Керування Docker-контейнерами

Для зручності наведено основні команди керування проєктом.

Перегляд запущених контейнерів:

```bash
docker compose ps
```

Перегляд журналів роботи сервісів:

```bash
docker compose logs -f
```

Зупинка контейнерів:

```bash
docker compose down
```

Повторний запуск проєкту:

```bash
docker compose up -d
```

**Примітка:** команда `docker compose down` не видаляє іменований том `db-data`, тому дані PostgreSQL зберігаються після зупинки контейнерів.

Для повного видалення контейнерів разом із даними бази даних можна виконати:

```bash
docker compose down -v
```

ця команда видаляє іменований том `db-data` разом із даними PostgreSQL.
